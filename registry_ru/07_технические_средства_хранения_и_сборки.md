# Технические средства хранения исходного кода, объектного кода и сборки

## Назначение документа

Документ описывает рекомендуемый контур хранения и сборки ПО "Аралтыш" для подготовки к включению в реестр российского ПО.

## Текущее состояние

На текущем этапе публичные зеркала проекта размещены на:

- GitHub;
- GitHub Container Registry;
- Docker Hub;
- npm.

Эти площадки удобны для публичного распространения, но не должны быть единственным основным контуром для заявки в реестр.

## Рекомендуемая целевая схема

Основной контур для реестра:

- исходный код: GitFlic, GitVerse или self-hosted Git-сервер на российском VPS;
- сборка: CI runner на сервере в Российской Федерации;
- объектный код: российский container registry или архив релизного Docker-образа на сервере в Российской Федерации;
- резервные копии: российское облако или отдельный сервер в Российской Федерации.

Дополнительные публичные зеркала:

- GitHub;
- Docker Hub;
- npm;
- GHCR.

## Вариант 1: GitFlic

1. Создать организацию или личный аккаунт GitFlic.
2. Создать приватный или публичный репозиторий `araltysh`.
3. Загрузить исходный код.
4. Настроить CI/CD runner на российском сервере.
5. Собирать Docker-образ внутри российского контура.
6. Хранить релизные артефакты в российском registry или в архиве.

## Вариант 2: GitVerse

1. Создать проект в GitVerse.
2. Загрузить исходный код.
3. Настроить доступы и ветки.
4. Использовать российский runner или локальную сборку на сервере.
5. Хранить релизные артефакты в российской инфраструктуре.

## Вариант 3: self-hosted Git

Можно развернуть на российском VPS:

- GitFlic self-hosted;
- Gitea;
- GitLab CE.

Минимальный набор:

- Git repository;
- доступ по SSH;
- резервное копирование;
- CI runner или ручная сборка;
- хранилище артефактов релиза.

## Требования к сборке

Сборка должна выполняться из исходного кода, размещенного в основном российском контуре.

Команда сборки:

```bash
docker build -t araltysh:X.Y.Z .
```

После сборки рекомендуется фиксировать:

- версию;
- Git commit hash;
- дату сборки;
- hostname/сервер сборки;
- checksum образа или архива.

## Что нужно заполнить перед подачей

- выбранная российская платформа хранения исходного кода;
- адрес российского репозитория;
- адрес сервера сборки;
- физическое или договорное размещение сервера в РФ;
- способ хранения объектного кода;
- регламент резервного копирования.
